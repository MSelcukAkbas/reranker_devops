# Lossless view (2026-09-30, searchslim 0.6.0)

Offline benchmark, 27 tasks, chars/4 tokens, raw total 76,565 tokens.
`python3 benchmark/bench.py run --tokenizer chars --view V --max-tokens M --trigger-tokens T`.

| setting | tokens | vs raw | kept | recoverable | lost |
|---|---|---|---|---|---|
| raw | 76,565 | 100% | 36/36 | 0 | 0 |
| 0.4 hook default: coverage, budget 2000, trigger 6000 | 48,499 | 63% | 36/36 | 0 | 0 |
| **0.6 hook default: lossless, max 7000, trigger 1500** | **42,924** | **56%** | **36/36** | 0 | 0 |
| lossless, max 2000, trigger 0 (forced tight) | 25,941 | 34% | 33/36 | 3 | 0 |
| notes, budget 2000, trigger 0 (0.3) | 30,497 | 40% | 32/36 | 4 | 0 |

At the defaults no fixture drops a match: 10 fixtures use L1 (grouping only), one
(`pytest-usage-error-p-option`, 24k tokens with `-C`) uses L1 without context lines
(4.3k tokens, every match kept), the rest pass through (below 1500 tokens or < 20% saving).
L1 alone, on every fixture, saves 31% (76.6k -> 52.5k); single-file searches save ~0
(no repeated path), path lists 20-41%, multi-file content 29-43%.

This measures context tokens only. The question the live run answers is whether
the agent still searches again (turns, billed cost): arvis_code, 4 tasks x 3, hook off vs 0.6.
