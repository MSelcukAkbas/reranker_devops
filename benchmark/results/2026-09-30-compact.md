# Test/build output compaction, offline (0.6.7)

`python3 benchmark/compact_bench.py` over `tests/fixtures/compact/` with the
compaction trigger at 0 (the hook and `run --compact` only act above 2000
tokens, so `jest.txt` and `go-vet.txt` stay unchanged live).

"Lost evidence" counts failure/error lines of the raw output that are neither
shown nor listed in a `more places` note. The diagnostic invariant itself
(every location kept or listed) is enforced by `tests/test_compact.py`.

Fixtures: real output of the tools (pytest, vitest, go test, cargo test, jest
30 --coverage, tsc 6.0, ESLint 10, gcc 13, cargo build, go vet), except
`dotnet-build.txt`, hand-built in MSBuild's format (no .NET SDK available).
The compiler/lint fixtures come from small generated projects with many
repeated mistakes, so they show what grouping can reach, not a typical
project: a build with mostly distinct messages saves far less (messages that
repeat fewer than 3 times are never grouped).
